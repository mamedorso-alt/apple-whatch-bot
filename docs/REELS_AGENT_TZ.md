# ТЗ: агент сценариев для Reels (бизнес / психология)

## Цель

Расширить существующий бэкенд (FastAPI + Telegram webhook + планировщик Apple Watch / отчёты) модулем, который **раз в сутки** формирует **один** сценарий короткого видео (Instagram Reels): **(1)** тема из бизнеса/психологии, где распространённое утверждение выглядит ложным, неточным или спорным; **(2)** опровержение с опорой на найденные в интернете факты, исследования или логику; **(3)** сценарий «хук — завязка — развязка», заточенный под удержание и продвижение в Reels. Результат доставляется **в Telegram** только со **ссылками из реального поиска** этого прогона.

Ручной запуск — **кнопка в чате** или **`/reel`**: бот сначала просит **тему / наброски**; следующее **свободное сообщение** (не команда) уходит в поиск и генерацию. **`/reel_auto`** — сразу случайная тема из интернета (как раньше). **`отмена`** / **`cancel`** — выйти из режима ожидания темы.

Ежедневная автоматическая отправка использует **случайный сид** (без ввода темы в Telegram).

## Ограничения и совместимость

- Не ломать текущие webhook-команды, отчёты, meal callbacks, sales, coach.
- Новый функционал **выключен по умолчанию** (`REELS_AGENT_ENABLED=false`).
- Получатели — только перечисленные в конфиге **Telegram user id** (личный чат с ботом).
- Ссылки в ответе: **только из результатов реального поиска** в этом прогоне (инструкция модели + передача сырья поиска).

## Архитектура

1. **Поиск** — DuckDuckGo (`duckduckgo-search`): старт с сида «миф/спорная тема»; второй проход по заголовку якоря («опровержение / исследование»); третий — смещение в сторону научных/фактчек источников (метаанализ, peer-reviewed, fact check), чтобы лучше закрывать шаг 2 ТЗ.
2. **Генерация текста** — тот же провайдер, что и коуч: **Anthropic Messages API** (`ANTHROPIC_API_KEY`), увеличенный таймаут для длинного ответа.
3. **Расписание** — `AsyncIOScheduler` в `worker.py` запускается, если **`SCHEDULER_ENABLED=true`** *или* **`REELS_AGENT_ENABLED=true`**. В тике: при `SCHEDULER_ENABLED` вызываются утренние/вечерние отчёты; **всегда** (при включённом reels) вызывается `run_reels_agent_scheduled`. Окно времени для дневного рилса задаётся **`REELS_AGENT_SEND_WINDOW_MINUTES`** (по умолчанию 120 минут с `REELS_AGENT_DAILY_HOUR:MINUTE`), чтобы тик не «промахнулся» из‑за интервала `SCHEDULER_INTERVAL_MIN`.
4. **Один раз в день на получателя** — таблица `reels_agent_daily_log`: уникальность `(telegram_user_id, delivery_date)` для отправок с пометкой `scheduled` (ручные запуски пишутся отдельно и **не** блокируют дневной автоматический).

## Конфигурация (env)

| Переменная | Назначение |
|------------|------------|
| `REELS_AGENT_ENABLED` | `true` — включить фичу |
| `REELS_AGENT_TELEGRAM_USER_IDS` | Список id через запятую, например `123456789` |
| `REELS_AGENT_DAILY_HOUR` / `REELS_AGENT_DAILY_MINUTE` | Локальное время отправки (окно как у утренних отчётов) |
| `REELS_AGENT_TIMEZONE` | IANA timezone; пусто = `DEFAULT_TIMEZONE` |
| `REELS_AGENT_ANTHROPIC_TIMEOUT_SEC` | Таймаут HTTP к Anthropic для длинного сценария |
| `REELS_AGENT_SEND_WINDOW_MINUTES` | Окно (минуты) после ежедневного времени, в котором может уйти автосценарий |

## Telegram UX

- **`/reel`** или кнопка — запрос темы; затем текст пользователя → поиск + сценарий. **`/reel_auto`** — сразу сценарий со случайной темой.
- Тексты кнопок: **«🎬 Сценарий рилса»** (ru) / **«🎬 Reel script»** (en) — обрабатываются **до** свободного текста коуча, чтобы не уходить в `/coach`.
- **ReplyKeyboardMarkup** показывается на **`/start`** и **`/help`** для пользователей из allowlist.
- Длинные ответы режутся на несколько сообщений (лимит Telegram ~4096 символов).

## Формат ответа пользователю

Структура генерируемого сообщения (на языке пользователя из `users.language`, иначе ru), в терминах трёх шагов продукта:

- **Шаг 1** — тема (одна строка)
- **Шаг 2** — спорное утверждение; затем опровержение и опора (данные / логика из сниппетов поиска)
- **Шаг 3** — сценарий Reels: хук (0–3 с) → завязка → развязка, с подсказками текста на экране и уклоном в удержание/продвижение (без выдуманных ссылок)
- **Источники** — только URL из этого поиска; в конце — короткий дисклеймер проверить ссылки перед публикацией

## Этапы реализации (фактически выполнены в коде)

1. Миграция БД и модель лога доставок.
2. Сервис `reels_agent` (поиск + Anthropic).
3. Сервис `reels_schedule` (окно времени, дедуп по дню для scheduled).
4. Интеграция в `worker._run_tick` и в `POST /internal/run-scheduled` (ключ ответа `reels_agent`).
5. Команда `/reel`, кнопка, разбиение длинных сообщений, строки i18n и README.

## Риски

- Качество и доступность DuckDuckGo может меняться; при пустом поиске — вежливое сообщение об ошибке без выдуманных ссылок.
- Модель может переформулировать; обязательная проверка человеком перед публикацией — в тексте дисклеймер.
