# ТЗ: AI-коуч продуктивности (полная спецификация v1)

## 1) Контекст и цель

### 1.1 Контекст
- В проекте уже есть рабочий контур:
  - Apple Watch/Health -> iPhone (HealthKit) -> Backend -> Telegram.
- Уже реализованы:
  - ingest метрик (`/v1/health/daily`),
  - scoring (`daily_scores`),
  - отчеты `/today`, `/week`.

### 1.2 Цель v1
- Добавить AI-коуча, который дает персональные рекомендации на основе:
  - последних health-данных,
  - score-тренда,
  - языка пользователя.
- Обеспечить стабильную работу даже без LLM за счет fallback-логики.

### 1.3 Ключевые принципы
- Не ломаем существующий pipeline.
- Изменения обратносуместимы.
- Любая внешняя зависимость (LLM) не должна делать систему хрупкой.

## 2) Scope: что входит и не входит

### 2.1 In scope (v1)
- API endpoint: `GET /v1/reports/coach`.
- Telegram command: `/coach`.
- Интеграция с Anthropic (Claude) через env.
- Rule-based fallback при любой ошибке LLM.
- Базовые тесты и обновление документации.

### 2.2 Out of scope (v1)
- Полноценный диалоговый агент с многошаговой памятью.
- Сбор произвольных пользовательских параметров (вес, рост и т.д.).
- A/B тестирование prompt-стратегий.
- Push-кампании с автономными напоминаниями.

## 3) Роли и каналы

- **iOS пользователь**: получает AI-отчет через приложение.
- **Telegram пользователь**: получает AI-отчет командой `/coach`.
- **Система**: выбирает язык и формирует безопасную рекомендацию.

Каналы доставки:
- API (`/v1/reports/coach`) для iOS.
- Telegram webhook (`/coach`).

## 4) Функциональные требования

### 4.1 Backend API
- Добавить `GET /v1/reports/coach` (Bearer token).
- Формат ответа:
```json
{
  "date": "YYYY-MM-DD",
  "report": "string"
}
```
- Локализация: `users.language` (`ru`/`en`).

### 4.2 Telegram
- Добавить поддержку `/coach` в webhook-роуте.
- Для непривязанного пользователя: существующая подсказка по `/link CODE`.
- Для привязанного: возвращать coach-report текущего дня.

### 4.3 Контекст для коуча
- Использовать последние N дней (`AI_COACH_CONTEXT_DAYS`, default 7):
  - `daily_metrics`: steps, active_kcal, sleep_min, resting_hr, hrv_sdnn, workouts_count
  - `daily_scores`: focus_score, mode
- Считать агрегаты:
  - today_score,
  - avg_score,
  - avg_sleep_min,
  - avg_steps.

### 4.4 Fallback (обязательный)
- Если `ANTHROPIC_API_KEY` пустой, таймаут, 4xx/5xx, парсинг-ошибка:
  - вернуть rule-based текст с конкретными действиями.
- Пользователь не должен видеть internal error/stack trace.

## 5) Нефункциональные требования

### 5.1 Надежность
- Timeout внешнего вызова: `ANTHROPIC_TIMEOUT_SEC`.
- Обработать все исключения в LLM-слое.
- Не допускать 5xx пользователю из-за LLM.

### 5.2 Безопасность
- Секреты только через env.
- Не логировать API ключи.
- Не передавать в prompt PII (телефон, chat_id, токены).

### 5.3 Производительность
- Один LLM вызов на один запрос.
- Ограниченный контекст (N дней).
- Ответ должен укладываться в нормальный UX Telegram/iOS (коротко и по делу).

### 5.4 Наблюдаемость
- Логировать технический исход:
  - `coach_provider=anthropic|fallback`
  - `coach_result=success|fallback|error_handled`
- Без чувствительных данных в логах.

## 6) Prompt/политика контента

- Коуч должен:
  - дать 1 краткий статус,
  - дать 2-3 actionable шага на сегодня.
- Коуч не должен:
  - ставить диагнозы,
  - давать медицинские назначения.
- Формат:
  - коротко, практично, без “воды”.

## 7) Архитектурные требования для масштабирования

Чтобы дальше не переделывать:
- Отделить слои:
  - data context builder,
  - provider client (Anthropic),
  - formatter/fallback.
- Подготовить путь к multi-provider в будущем:
  - единый интерфейс генерации,
  - конфиг-переключатель провайдера.
- Сохранить обратную совместимость существующих API.

## 8) Дорожная карта (после запуска приложения)

### Sprint 1 (текущий)
- Включить AI-коуч в prod-среде.
- Протестировать `/v1/reports/coach` и `/coach`.
- Верифицировать fallback-поведение без ключа и при ошибках.

### Sprint 2
- Добавить запись истории рекомендаций:
  - таблица `coach_messages` (user_id, date, channel, provider, model, response, metadata_json).
- Добавить endpoint истории (`/v1/reports/coach/history`).

### Sprint 3
- Добавить сбор недостающих данных:
  - профиль пользователя (вес, рост, цель),
  - правила запроса недостающих метрик (без спама).
- Telegram/iOS flow “мягкий вопрос + запись ответа”.

### Sprint 4
- Добавить feedback loop:
  - “помогло/не помогло” по рекомендациям.
- Персонализация на основе прошлого эффекта.

## 9) API контракты (v1 + зарезервировано)

### 9.1 Реализуется в v1
- `GET /v1/reports/coach` -> `{date, report}`.

### 9.2 Резерв для следующих этапов
- `GET /v1/reports/coach/history`
- `POST /v1/profile/metrics` (weight/height/goal)
- `GET /v1/profile/missing-data`

## 10) Тестирование и приемка

### 10.1 Обязательные тесты v1
- API integration:
  - auth -> ingest -> `/v1/reports/coach` -> 200.
- Telegram integration:
  - `/coach` для linked user -> `status=ok`.
- Fallback:
  - без `ANTHROPIC_API_KEY` -> корректный текст без 5xx.

### 10.2 Критерии приемки v1
- Коуч-отчет доступен из API и Telegram.
- Без ключа/при ошибке Anthropic пользователь получает рабочий fallback.
- `/help` и `/start` содержат `/coach`.
- Существующие `/today` и `/week` не деградируют.

## 11) Риски и меры

- Риск: нестабильность внешнего LLM API.
  - Мера: обязательный fallback + таймаут.
- Риск: шумные/слишком длинные ответы.
  - Мера: жесткий prompt-формат + ограничение длины.
- Риск: утечка чувствительных данных в prompt/log.
  - Мера: только агрегаты, без PII, sanitize логов.

## 12) Definition of Done

- Код, тесты, docs обновлены.
- `.env.example` содержит AI-переменные.
- E2E ручная проверка пройдена:
  - iOS sync -> `/coach` в Telegram -> валидный ответ.
- Подготовлен backlog на Sprint 2 (история/память) и Sprint 3 (missing data).
